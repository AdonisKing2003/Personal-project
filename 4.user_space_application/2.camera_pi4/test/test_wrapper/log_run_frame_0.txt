Tại Sao Phải Đợi Frame Đầu?
1. Camera Hardware Initialization
rpi_camera_start()
    ↓
Camera sensor power up (5-10ms)
    ↓
Auto exposure/white balance init (20-50ms)
    ↓
ISP pipeline warm up
    ↓
First frame ready (50-200ms total)
2. Buffer Flow Pipeline
[Sensor] → [Unicam] → [ISP] → [DMA] → [FrameBuffer] → [Your Pipeline]
   ↓          ↓         ↓        ↓          ↓              ↓
  5ms       10ms      20ms     5ms        5ms           10ms
Tổng latency frame đầu: ~50-100ms
3. Request Queue Mechanics

**Request đầu mất thời gian nhất** vì phải đi qua toàn bộ pipeline lần đầu.

### 4. **Tại Sao RGB888 640x480 Đặc Biệt Chậm?**

**Native resolution = No scaling overhead**

Với các resolution khác:
```
Sensor: 1920x1080 (native)
    ↓
ISP: Scale down to 1280x720  (buffer time: ~20ms)
    ↓
DMA transfer
```

Với 640x480:
```
Sensor: 640x480 (native mode)  
    ↓
ISP: Direct pass-through (buffer time: ~2ms)  ← CỰC NHANH!
    ↓
DMA transfer
Paradox:

Processing nhanh hơn (2ms vs 20ms)
Nhưng first frame xuất hiện chậm hơn vì:

Sensor phải switch mode sang 640x480
Auto-exposure phải recalibrate cho resolution mới
Timing parameters khác hoàn toàn

Steady State Operation

    // ↓
    // Total cycle: ~57ms (17.5 FPS)

**Pipeline đã "ấm":**
- ✅ Sensor running steady
- ✅ ISP buffers pre-filled  
- ✅ DMA channels active
- ✅ Requests cycling smoothly

### Buffer Pre-filling
```
Queue size = 4 requests

T=0:    [R1] [R2] [R3] [R4] queued
T=50:   [R1] completes → pipeline
T=57:   [R2] completes → pipeline  
T=114:  [R3] completes → pipeline
        [R1] requeued ← Now cycling!
T=171:  [R4] completes → pipeline
        [R2] requeued
```

**Sau 4 frames đầu, pipeline vào "cruise mode":**
- Luôn có requests đang chờ
- Zero gap giữa các frames
- Throughput tối đa

## Test Case Của Bạn

### Không đợi frame đầu:
```
T=0ms:    start()
T=0ms:    Loop bắt đầu try_pop()
T=0-150ms: Pipeline TRỐNG → try_pop() fail liên tục
T=150ms:  Frame đầu arrive
T=2000ms: Stop (chỉ có ~1.85s để capture thực sự)
Result: 0 frames (stopped trước khi frame đầu ready!)
```

### Đợi frame đầu:
```
T=0ms:    start()
T=150ms:  Frame đầu arrive (đợi ở đây)
T=150ms:  Loop bắt đầu
T=150-2150ms: Capture đầy đủ 2 giây
T=2150ms: Stop
Result: ~35 frames (17.5 FPS × 2s)
Kết Luận
Cold start latency là hiện tượng bình thường trong camera systems. Best practice:
cpp// Production code
rpi_camera_start(cam);

// Warm-up: discard first 3-5 frames
for (int i = 0; i < 3; i++) {
    rpi_frame_t frame;
    while (rpi_camera_try_get_frame(cam, &frame) != 0) {
        usleep(10000);
    }
    rpi_camera_release_frame(&frame);
}

// Now stable, start real capture
Đây là lý do camera apps thường có "preview" mode trước khi capture!
