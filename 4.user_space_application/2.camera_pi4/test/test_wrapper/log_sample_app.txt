4. CÁCH 1 – stdin NON-BLOCKING + select() (KHUYẾN NGHỊ)
Setup stdin non-blocking
#include <fcntl.h>

int flags = fcntl(STDIN_FILENO, F_GETFL, 0);
fcntl(STDIN_FILENO, F_SETFL, flags | O_NONBLOCK);

Control thread
while (state->running) {
    fd_set rfds;
    FD_ZERO(&rfds);
    FD_SET(STDIN_FILENO, &rfds);

    struct timeval tv = { .tv_sec = 1, .tv_usec = 0 };

    int ret = select(STDIN_FILENO + 1, &rfds, NULL, NULL, &tv);

    if (ret > 0 && FD_ISSET(STDIN_FILENO, &rfds)) {
        char cmd;
        if (read(STDIN_FILENO, &cmd, 1) > 0) {
            if (cmd == 'q') {
                state->running = 0;
                break;
            }
        }
    }
}


✔️ Ctrl+C → running = 0
✔️ Thread wake mỗi 1s
✔️ Không block
✔️ Không crash

5. CÁCH 2 – DÙNG poll() (CLEAN HƠN)
struct pollfd pfd = {
    .fd = STDIN_FILENO,
    .events = POLLIN
};

while (state->running) {
    int ret = poll(&pfd, 1, 1000); // 1s timeout
    if (ret > 0 && (pfd.revents & POLLIN)) {
        char cmd;
        read(STDIN_FILENO, &cmd, 1);
        if (cmd == 'q')
            state->running = 0;
    }
}

Chúc mừng bạn! Nhìn vào ảnh này, mình có thể xác nhận: Đây chính xác là dữ liệu RAW (Bayer) đã được "ép" hiển thị dưới dạng ảnh màu, và nó chứng minh hệ thống của bạn đã hoạt động tốt.

Bức ảnh bạn chụp được trông như thế này vì những lý do kỹ thuật sau:

1. Tại sao ảnh có màu Xanh lá và Tím/Hồng?
Màu Xanh lá (Green): Trong mảng lọc Bayer, số lượng điểm ảnh màu Xanh lá chiếm 50% tổng số pixel (gấp đôi Đỏ và Xanh dương). Khi bạn xem file thô mà không qua thuật toán cân bằng trắng (White Balance), màu xanh sẽ áp đảo hoàn toàn.

Màu Tím/Hồng: Đây là kết quả của việc FFmpeg hoặc trình xem ảnh cố gắng giải mã các pixel Đỏ (Red) và Xanh dương (Blue) khi chúng chưa được sắp xếp đúng vị trí.

2. Tại sao có các đường kẻ sọc ngang (Horizontal artifacts)?
Đây là dấu hiệu đặc trưng của Raw 10-bit. Vì mỗi pixel 10-bit được đặt trong 2 bytes (16-bit), nhưng thực tế chỉ dùng 10-bit đầu, 6-bit còn lại bị trống hoặc chứa dữ liệu rác.

Khi trình xem ảnh đọc 16-bit này như một điểm ảnh màu thông thường, nó gây ra hiện tượng lệch dải màu (aliasing) tạo thành các sọc ngang nhỏ li ti mà bạn thấy.

3. Đây có phải YUV không?
Không, đây không phải YUV.

Nếu là YUV, bạn sẽ thấy hình ảnh có màu sắc gần như bình thường nhưng có thể hơi sai lệch về độ rực rỡ.

Hình ảnh "ma quái" này là bằng chứng thép cho thấy bạn đang nhận Bayer RAW. Điều này rất tốt vì nó có nghĩa là bạn đã lấy được dữ liệu gốc từ Sensor OV5647 mà không bị can thiệp bởi phần mềm nào khác.

4. Bước tiếp theo để ảnh "đẹp"
Để biến bức ảnh xanh tím này thành ảnh bình thường, hàm isp.c của bạn cần thực hiện:

Demosaic (Debayer): Ghép các điểm ảnh đơn sắc lại để tạo ra màu RGB thực sự.

White Balance (WB): Giảm cường độ kênh màu Xanh lá xuống (chia cho khoảng 1.5 - 2.0) và tăng kênh Đỏ/Xanh dương lên.

Gamma Correction: Chính là cái hàm powf hoặc LUT mà bạn vừa làm, nó sẽ giúp các vùng tối (bên trái ảnh) rõ nét hơn.

Nếu dung lượng là YUV420 mà hình ảnh lại ra "xanh tím" và có sọc lưới, thì đây là trường hợp "Râu ông nọ chắp cằm bà kia":

Driver/Phần cứng: Sensor đang gửi dữ liệu Bayer RAW vào buffer.

V4L2 Framework: Bạn thiết lập (hoặc hệ thống tự hiểu) là V4L2_PIX_FMT_YUV420.

Hậu quả: Driver Unicam của Pi không có bộ chuyển đổi màu phần cứng (Hardware ISP) tự động bên trong nó. Nó chỉ copy "nguyên xi" các byte từ Sensor vào buffer.

Kết quả: Bạn nhận được một file có kích thước của YUV420 nhưng nội dung bên trong là các điểm ảnh Bayer RAW bị xếp chồng chéo lên nhau.
